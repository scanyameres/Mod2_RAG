# Data format: Kolumna.org articles

What one downloaded article looks like, which values are fixed, which come from a controlled list and which are free text. Measured on 2026-11-23.

Two data sets were measured:

- **All 2026 posts (1,593)**: public metadata only (no article text). Used for every count below unless stated otherwise.
- **Sample (48)**: one article per calendar week of 2026, with full text, stored in `data/raw/kolumna_sample_2026.jsonl`. Used for everything about the article body.

## File

`data/raw/*.jsonl`: JSON Lines, UTF-8, one article per line, one JSON object per article. Source: the WordPress REST API of kolumna.org (`/wp-json/wp/v2/posts`), called with a signed-in subscriber session. The folder is git-ignored.

## Fields of one record

| Field | Type | Kind | Filled | Notes |
|---|---|---|---|---|
| `id` | int | system | always | WordPress post ID. Unique key. Grows over time but not strictly with the publication date. |
| `date` | string | system | always | Publication time, `YYYY-MM-DDTHH:MM:SS`, local time (Europe/Berlin), no time zone suffix. |
| `modified` | string | system | always | Last edit, same format. Differs from `date` in 78% of posts; more than one day later in 19%. Can be *earlier* than `date` (6 posts: scheduled publication). |
| `url` | string | system | always | Always `https://kolumna.org/<slug>/`. |
| `slug` | string | free | always | Usually derived from the first title. 28 posts have a numeric slug such as `40756-2` (created before a title existed). Does not change when the title is edited later. |
| `title` | string | free | 1 empty | Plain text, but with HTML entities (`&#8211;`, `&amp;` ...) that must be decoded. No HTML tags in the sample. |
| `excerpt_html` | string | free | always | Teaser as HTML (`<p>...</p>`). Two kinds: hand-written (47%, 6 to 74 words) or generated by WordPress from the first 55 words of the body, ending in `[…]` (53%). |
| `content_html` | string | free | always present, 3 of 48 without text | Article body as HTML. See "Article body" below. |
| `author_id` | int | controlled | always | WordPress user ID. Maps one-to-one to `author`. |
| `author` | string | controlled | always | Byline. 20 different values in 2026. `Redaktion` (no named journalist) is 38% of posts; `Werbung` marks advertising. |
| `category_ids` | list of int | controlled | always, 1 to 3 | See "Categories". |
| `categories` | list of string | controlled | always, 1 to 3 | Names for `category_ids`, same order. 96% of posts have exactly one. |
| `ort_ids` | list of int | controlled | 7% empty | Municipality (custom taxonomy `ort`). |
| `orte` | list of string | controlled | 7% empty | Names for `ort_ids`. 88% of posts have exactly one, 5% have 2 to 7. |
| `source` | string | added by us | always | Where the record came from. |
| `fetched_at` | string | added by us | always | Download time, ISO 8601 in UTC (`...Z`). |

"Kind" means: **system** = set by WordPress, strict format; **controlled** = picked from a fixed list maintained by the editors; **free** = typed or pasted by the editors, no rules enforced.

### Fields of the API that carry no information

Constant for all 1,593 posts, so they are not stored: `status` (`publish`), `type` (`post`), `format` (`standard`), `template` (empty), `sticky` (`false`), `comment_status` (`open`), `acf` (empty), `meta` (same value everywhere). WordPress `tags` are not used (one post has tags). `featured_media` (a picture ID) is set for every post.

### Useful API fields not in the sample file

Candidates for the full download: `date_gmt` (publication time in UTC), the estimated reading time in minutes and the main picture URL (both inside `yoast_head_json`, filled for every post).

## Article body (`content_html`)

The body is free-form HTML with no enforced structure. Observed in the 48 sample articles:

- **Text**: mostly `<p>` paragraphs. One article keeps its text in `<div>` elements without any `<p>`.
- **Subheadings**: `<h4>` in 20 articles, `<h3>` in 2. No `<h2>`.
- **Pictures**: 44 `<img>` in 12 articles. 27 sit in a `<figure class="wp-caption">` with a `<figcaption>` (5 to 41 words, median 14; 11 of them name a photo credit). The other 17 are bare `<img>` without caption.
- **Links**: in 23 articles; 7 link to other websites.
- **Quotes**: `<blockquote>` in 2 articles.
- **Leftovers from copy and paste**: `style` attributes (18 articles), non-breaking spaces (24), empty paragraphs (12), and class names from other programs (`Apple-converted-space`, `mcePastedContent`, `p1`, `layoutArea`). These carry no meaning.
- **Page-builder blocks**: 4 articles wrap content in layout `<section>` elements (`l-section`, `vc_row`).
- **Video-only posts**: 3 articles (all Sport) contain only an embedded Streamable video. Without cookie consent the body is a 39-word consent notice starting "Sie sehen gerade einen Platzhalterinhalt von streamable". These posts have no article text.

### Consequences for processing

- Convert the body to plain text by taking the text of all elements, not only of `<p>`.
- Remove consent placeholders (elements with a class starting `brlbs-`) and treat posts with no remaining text as video-only.
- Decide whether captions belong to the text (they add photo credits and short descriptions).
- Decode HTML entities in `title`; normalise non-breaking spaces and repeated whitespace.
- Do not use `excerpt_html` as a summary without checking: half of the excerpts are just the first 55 words of the body.

## Open points

- All body observations rest on 48 articles. They need to be re-checked on the full download, in particular the share of video-only posts.
- Whether other embeds (YouTube, podcasts, social media) appear in the body: none in the sample.
